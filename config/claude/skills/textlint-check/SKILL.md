# textlint-check

日本語の Markdown に 2 つの検出器をかけ、指摘をまとめて報告し、修正する。

| 検出器                     | 対象                                                                           |
| -------------------------- | ------------------------------------------------------------------------------ |
| textlint                   | `~/.textlintrc.json` のプリセット（技術文書の規約・AI 語彙・全角半角スペース） |
| natural-japanese `lint.py` | 形態素解析による AI らしい書き癖（翻訳調・定型句・対比の反復・単調なリズム）   |

どちらも dotfiles が配る。textlint は `~/.npm-global`、`lint.py` は mise の `http:natural-japanese` にある。

## ワークフロー

### 1. 対象の特定

会話中に貼られたテキストは `mktemp -t textlint-check.XXXXXX.md` で作った一時ファイルに書き出してから渡し、作業後に消す。

### 2. 実行

2 つを並べて実行する。

```bash
textlint <対象ファイル>
uv run "$(mise where http:natural-japanese)/skills/natural-japanese/scripts/lint.py" --genre tech <対象ファイル>
```

- textlint は指摘が 1 件でもあると終了コード 1 を返す
- `lint.py` は指摘の有無にかかわらず終了コード 0 を返す。1 になるのはファイルが読めないときだけ
- `lint.py` の出力末尾の「段落ごとの確かめ」は natural-japanese 本体の推敲手順向けなので、この skill では使わない
- `--genre` は文書に合わせて `tech` / `business` / `essay` から選ぶ。技術文書以外の報告書・議事録は `business`
- 長い文書では `lint.py` に `--reading-load` を足すと、一文の長さや連続する漢字など読みにくさの指摘も出る

### 3. 報告

- 検出器ごと・ルール（カテゴリ）ごとの件数を表にまとめる
- 同じ行に同じ趣旨の指摘が両方から出たら（例：`preset-ai-writing` と `lint.py` の `forbidden_phrase`）、1 件にまとめて両方のルール名を添える
- textlint の自動修正できる指摘（`✓` 付き）と、本文を読んで直す指摘を分けて示す
- 本文を読んで直す指摘は、該当箇所の原文を添える。`lint.py` の指摘は「直し方」もそのまま添える

### 4. 修正

1. textlint の `--fix` で自動修正できるものを処理する（→ 注意事項）

   ```bash
   textlint --fix <対象ファイル>
   ```

2. 残った指摘を、本文を読んで直す
3. 2 つの検出器をもう一度実行し、指摘が解消したことを確認する

## 注意事項

- `--fix` は文章全体に一括で効く。全角・半角間スペースの指摘が大量に出ても、英単語の前後のスペースは意図的なことがあるので、`--fix` の前にどのルールが自動修正されるかをユーザーに確認する
- `lint.py` の指摘は疑いであって誤りの断定ではない。直すかどうかは文脈を読んで決め、直さないものは理由を添えて残す
- 直すときは元の文書にない事実・数値・意見を足さず、確信の度合いも変えない（「検討する」を「決定した」にしない）
- コードブロック・テーブル内の指摘は誤検出のことがある。原文を確認してから直す
